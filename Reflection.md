# Reflection

- **Design decision**. I exposed RAG through the AgentCore Gateway's Bedrock Knowledge Base connector instead of hand-writing a `search_knowledge_base` tool. The connector already publishes the Retrieve API as an MCP tool, so a custom wrapper would have given the model two near-identical tools to choose between. The trade-off was tool selection: the connector's default description is generic, so I set a use-case-specific one with `--description` when creating the target, naming return policies, warranties, and loyalty tiers. The result is one tool per capability, configured declaratively rather than coded.

- **Challenge**. The hardest problem was the browser tool. Strands' `AgentCoreBrowser` crashed the server: its initializer replaces the asyncio event loop, which (per an open upstream issue) corrupts anyio's internal state under Python 3.14 and breaks every later request. After several failed workarounds I stopped fighting the abstraction and went one layer down. I used the boto3 `BrowserClient` to start the managed browser session and drove it with raw Chrome DevTools Protocol messages over a WebSocket, in a dedicated thread with its own `asyncio.run()` so it can never touch the server's event loop. This also removed Playwright, which cannot run in the runtime's read-only container. The lesson: when a wrapper's assumptions conflict with its host, isolate the integration and use the lower-level API.

- **Production**. First, security. The Gateway currently has no authorizer, and `user_id` is a payload field any caller could spoof; I would add JWT or IAM authorization and derive customer identity from verified claims. The browser returns untrusted page text to the model, so I would add a URL allowlist and treat page content strictly as data. The inline IAM policies I attached by hand to the runtime role belong in infrastructure code, scoped to least privilege. Second, reliability. The loyalty calculator and memory hook degrade gracefully but silently (my loyalty tool quietly returned a tier-only answer when its IAM permission was missing), so I would add metrics and alarms on every fallback, plus timeouts on all external calls. Finally, I would pin dependencies, add automated regression tests for the six scenarios, and consider a container build for tighter control of the runtime.
